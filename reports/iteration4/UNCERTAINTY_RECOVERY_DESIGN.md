## 推荐最小方案 A：恢复定位 + 逐项显式裁定，不开新发布通道

1. **正向定位，不猜归属。** 以当前实际单元目录为准；只有原字符串在首个非空白位置以完整实际 `unit.id` 开头，且紧随明确空白、冒号或中文冒号，才绑定。按实际 ID 最长匹配以保护 `.answer` 等合法 ID；正文中顺带提及 ID、同节外 ID、模糊前缀、未提供单元均不自动定位。正则如有使用，只作有界定位，绝不删除或改写原疑点。
2. **原记录不可变。** 保留 `WrittenSection.uncertainties`，仍只允许 LocalPatch 的 `uncertainties_append`。为每条原文保存完整文本、原数组索引和完整原文哈希，不用 mathcheck 显示用的 1000 字截断作为身份。报告同时保留原 math 输出与后续处置；去掉 Pipeline 第二次无定位注入，而不是删原数组。
3. **独立窄 schema/角色。** 只在存在声明疑点的节调用专用裁定；不重写通用 MathReview/schema/reviewer_math 提示词。输入包括全部原疑点及稳定 ID、实际当前单元、真实 prior_sections、批准计划、已有工具证据及实际普通数学复核。复用实际数学审阅链，不让裁定者重规划课程。
4. **每条固定 ID 必须有显式结果。** 建议三个结果：`resolved_by_current_body`（实际新正文/先修已提供解决依据）、`open_actionable`（存在已定位且批准范围内的可修正文缺口）、`open_dependency`（外部依据/授权尚缺，改措辞不能解决）。每条含 reason、目标 ID、实际正文逐字引文；解决结论还需证明链或实际来源的具体引文与来源哈希。无回答、空列表、笼统“已核对”、不存在的引文不得当消解。这里的 resolved 仅是该条声明疑点的有证据模型处置，不是形式化证明。
5. **只处置所属声明疑点。** `resolved_by_current_body` 仅使对应 `DECLARED_MATH_UNCERTAINTY` 不再作为重复修正文目标，不能抹掉普通 MathReview 的独立 blocking/review、核算 UNKNOWN、确定错误、未授权先修或范围问题。`open_actionable` 进入既有严格 LocalPatch；`open_dependency` 保存阻断及所缺依据，避免无依据反复改写。当前 CH03 即使正确定位，也不因此自动解除指数疑点。
6. **限定重放。** 身份绑定批准 plan/revision、完整原疑点、实际正文和实际依赖、工具证据、专用 prompt/schema/helper。job ID 作为来源证据，而不能靠新 job、换模型或普通重试使同一数学事实获得新抽签机会。已有有效未决/无效裁定在同一身份上重放阻断；仅供应商传输失败可在同一已冻结槽位继续完成一次裁定。真正新正文或新核验依赖可触发新身份，但旧记录和计数保留。
7. **先落盘普通结论。** 在发新裁定请求前保存原普通 MathReview、全部原问题、输入和身份；任何失败恢复不得重抽普通 review 到空 PASS 后丢旧疑点。复用现有持久化核实机制的约束，不另建无限重试环。保留 request 总数、逐单元 accepted/proposal/rejected 和 global rounds，不重新初始化 LocalRecovery。
8. **旧状态迁移须可证明。** 当前遗留无类型重复项，只有完整文本等于该已保存候选的原 uncertainty、原候选哈希及原 review 证据均验证时，才能记作同一疑点的显示重复；记录迁移映射。不能用 message 相似度清理普通 reviewer issue；截断碰撞或来源不明就保留阻断。新裁定结果哈希进入局部 review identity，避免同身份旧疑点合并逻辑把合法新处置当作空 review，或反向清掉无关疑点。

局部建议 schema 的核心字段为：`items[{uncertainty_id, disposition, reason, unit_ids, body_evidence[{unit_id,quote}], dependency_evidence[{source_key,source_sha256,quote}], repair_instruction}]`，顶层 `limitations`。来源只可引用本次实际提供、已核验的材料，不能由模型给任意 URL 或路径宣称已查。`resolved_by_current_body` 的引文可以本地验证存在，但数学推理有效性仍须真实模型/教师核查，如实标记其证据类型。

实现文件预计为新窄 helper/schema、专用 prompt、Pipeline 接口和 MockProvider 新角色；mathcheck 的原始事实保留。若选择在 mathcheck 自身补位置可单列窄改动，但不更改其 UNKNOWN 语义。当前 section contract 包含 Pipeline 和 mathcheck 全文件 SHA；这次任何 Pipeline 修订本来就会使旧 CHECKED 重检，不能谎称不会产生重检，也不宜为了省调用绕过契约。无 uncertainties 的节不增加专用裁定 API。应与已计划的全局 LocalPatch 修复一次合并，减少反复部署。
