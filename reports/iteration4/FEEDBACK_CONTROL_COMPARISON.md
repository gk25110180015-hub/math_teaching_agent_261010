# 逐项反馈协议：真实对照与保留的差异

两版本使用完全相同的两组输入和本地预期，共 **4 次真实 gpt6 / gpt-6-astra 请求**。均返回 HTTP 200、完整 SSE 和有效 JSON/schema；无备用模型调用。模型接口成功与业务证据校验、教学判断符合度分别统计。[原始账本与指纹](FEEDBACK_CONTROL_COMPARISON.json)

| 版本与用例 | 观察结果 | 严格本地预期 |
|---|---|---|
| v1：CH03 三项意见 | F1 已满足，F2/F3 需改；但依据单元与修改目标混为一个列表，S03.U05 被列入目标而指令要求保留它 | 分类 PASS；发现实际修复范围协议缺陷，不能据此宣称完整闭环通过 |
| v1：已满足与越界 | 语义上正确区分已满足与越界；F2 多列 S02.U04 却未给该项对应引文，本地校验阻断 | FAIL，原回复保留；不是 API 连接失败 |
| v2：CH03 三项意见 | 引用依据与 repair_unit_ids 分开；F2/F3 正确需改；F1 认为示范已有、仍可补独立练习 | FAIL：固定预期要求 F1=satisfied；没有修改预期或重抽至 PASS |
| v2：已满足与越界 | F1=satisfied，F2=out_of_scope，实际修复目标均为空，依据校验通过 | PASS |

v2 的两份回执均通过逐项覆盖、逐字证据与明确修复目标校验；生成动作与 repair_unit_ids 完全对应。第一组 F2 只要求修改 S03.U08，未把仅作为已有定理依据的 U05/U06 改写。F3 的修改限定在原有题目和对应答案；不修改批准计划或增设单元。

v2 的 F1 差异有具体理由：模型认可 S02.U04 已有完整示范，但认为原反馈中的学生训练要求仍可由 U12/U13 的独立练习加强。该结论需要与原目标及实际正文一起审读，不能简单当作数学错误，也不能把严格 FAIL 改写成 PASS。本轮保留此结果，由实际章节复检和独立审计继续核对效果。

独立审读随后核对了该版本的原反馈、71 个单元中的夹逼正文和全部 7 道练习：已有完整示范，但没有一题要求学生独立使用夹逼定理；S02.U12 原为已知极限下的商法则计算。原反馈确实提及练习及答案，批准目标也要求能运用夹逼计算。因此，在现有题及答案中补一个短小、区别于原示范的小问有教学依据，且回执明确排除了重写已正确的 U04。此判断解释了分歧，**没有改变严格评分 FAIL**，也没有把新增练习视为数学纠错。

v1 的过宽修改目标促成 schema 增加 repair_unit_ids；v1 的无引文单元仍被严格拒绝，没有靠跨项借用证据或放宽该项覆盖校验放行。合理的纯越界请求可只给真实批准范围依据而没有正文修改目标。所有拒绝、尚未确认和待改进结果会在新界面按条展示，不用空问题列表代表意见全部落实。

这些是两个已知用例的针对性回归，并非随机盲测、总体数学准确率或提示词因果效果估计。预期只用于本地评分，没有发给模型；没有模型权重训练。新版 schema/prompt 有实质修正后才运行第二批，原批次未覆盖。后续仅对最终 helper 离线复核保存响应，不为抹去有效分歧增加同题重抽。

本对照未执行 Windows 编译、PDF 视觉检查或教师签认，均为 NOT_RUN；它也没有修改真实章节任务。实际工作流接入、Windows 编译与文件交付须看后续独立证据。
