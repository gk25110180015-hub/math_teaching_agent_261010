## 协议与恢复审查

- 固定反馈分母来自原始编号，模型不能少报项目来完成任务。非连续或未编号文本保留为整段 F1；这是有界能力，不声称任意自然语言自动分解。
- 五种状态均有理由；supported_improvement 明确是教学改进，可以通过原定点修复路径行动，不要求伪称数学错误。每项实际正文引文及批准目标本地核对，空白引文不能借空字符串匹配绕过。
- evidence unit_ids 与 repair_unit_ids 分离，后者须为实际证据单元的合法子集。已正确的定理可以作为依据，不能因此自动成为修改目标。导航可以引用真实 lecture 配置；越界请求可以没有对应单元，但须引用真实批准范围。
- 普通数学阻断项先走原修复循环；仅在普通阻断清除后评估反馈，避免反馈失败丢失既有数学问题。累计请求、全局轮次、原批准身份没有重置。
- 每个 job、批准 plan、正文、反馈与检查契约绑定持久槽。已收到的无效或未决完整响应持久阻断，同一身份重试不能反复抽样；传输或预算失败恢复原槽，BUDGET_EXHAUSTED 保留原增额恢复机制。保存响应、孤立响应、文件篡改、租约过期均有对应控制。
- API 读取当前动作对应的最新回执，invalid/pending 不能显示旧成功结果；同时间记录有 rowid 次序。共享 schema 支持真实合法 `.answer` ID，不额外杜撰身份规则。UI 用文本节点展示理由、证据及实际修改目标，轮询指纹含回执，保留未提交草稿。
