## 已接入应用的改动

- 原 CH02、CH03 通过正式预算 API 从 60/2/2 增至请求 240、每单元修复 6、全文修复 6，累计请求、已接受修改、被拒提案和原审批不清零。拒稿次数限制随显式预算调整；全文额度提高后能从已用轮次继续修复原疑点。见 [预算与审批证据](budget-authorization-and-preservation.md)。
- 章节检查点绑定检查代码、提示词、schema、依赖与编译配置；新规则及前文变化会触发对保留稿的重新检查。真实 SQLite 多版本检查点按明确顺序选择；没有编译检查点的最新合法稿、连续中断、上游修订后重启均保留修复状态及证据。
- 等待人工复核的任务增加“重新运行自动检查”按钮及 API。旧交付进入历史区继续下载，新的预览、质量报告与逐页复核使用当前产物；旧复核不能替新文件签字。自动动作不提交教师审核。
- 级数核算在调用收敛性判断前保留原表达式的定义域约束，避免把首项无定义的级数误判为通过。无法证明所有项有定义时返回 UNKNOWN。正文另有范围明确的对数级数起点扫描，定位具体单元并要求复核，不能充当任意 TeX 数学证明器。
- 讲义在单节、相邻节之外新增一次全章教学目标审阅；检查一般结论、参数范围、边界、索引约定、例练支持和学生可读引用。可见内部单元编号进入局部修复。审阅 v6 要求结合连续定义的完整条件判断，不用不满足原假设的反例制造阻断。
- 能由真实编译日志精确映射至当前单元的溢出进入既有局部补丁、数学复查及重新编译流程。每次编译使用独立目录并绑定源文件、日志和 PDF 哈希；排版疑点持续保留到真正编译通过，重试也不能借缩字号、缩放或提高容差放行。不明位置、跨单元或其它编译错误保持明确失败。
- 同一批准计划的全局修复契约发生不兼容改变时明确阻断并保留旧轮次；本轮没有实现任意旧契约的自动迁移，不以升级为由重新从零计数。
- `Run-ExtendedReview.ps1` 可启动原独立应用，连接/读取/单次总等待为 30/600/600 秒。仅通过进程环境传递非密钥超时参数；三模型配置与首选顺序保持不变。它不能延长供应商自身的网关期限。
